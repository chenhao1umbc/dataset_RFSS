Workflow Pain Points — RFSS Project

Recorded 2026-02-20. Items for the automation roadmap.

1. Agent Workflow

Pain Severity Detail Status Target fix
Manual CC2 review invocation High After CC1 finishes work, user must manually switch to CC2 and ask it to review. No automation, no handoff trigger. Open orchestrate.py integration + review/ handoff protocol
Task completion gate is manual High tasks.md can only be marked complete after CC2 approves. Currently requires human to coordinate between sessions. Open Automated approval write-back from CC2
CC1 violated reviewer independence High CC1 initially claimed to be both coder and QC reviewer — reviewing its own work, which cannot catch logic flaws. Acknowledged Two independent CC sessions enforced by design
Writer/reviewer agents lack project context High orchestrate.py agents (writer.md, reviewer.md) have no knowledge of the RFSS codebase, 3GPP standards, or coding conventions. Cannot be used for project coding yet. Open Project-level agent definitions + codebase onboarding step

2. Data Generation

Pain Severity Detail Status Target fix
HDF5 corruption on process kill High Killing the generation process left HDF5 superblock unflushed. File became unreadable (addr overflow). 39k samples lost twice. Fixed DatasetWriter.flush() called every 1000 samples before checkpoint save
Mac sleep killed background jobs Med Generation runs for ~7 hours. Mac sleep suspended/killed the process. User had to point this out. Fixed caffeinate -i in run_generation.sh
No progress monitoring initially Med Background job launched with no visibility into progress. User rightly called this out as wasted time. Fixed data/monitor.py — polls every 5 min, logs ETA, sends macOS notifications at 25/50/75/100%
Generation log appends across runs Low generation.log uses >> so old and new runs are mixed. Confusing to read — old "Resuming" messages looked like current state. Open Timestamp-separate log files per run, or clear separator on restart
5G NR sample_rate bug in ParameterSampler High Sample rate was fixed (30.72 MHz for μ=1, 122.88 MHz for μ=3) regardless of actual bandwidth. Channel models and impairments applied at wrong rate — physically incorrect. Fixed NR_SAMPLE_RATES lookup table; actual rate now used throughout
μ=3 large bandwidth configs too large Med μ=3 with 200/400 MHz gives 245/491 MHz sample rates — signals up to 491k samples/ms. HDF5 pre-allocation would be ~393 GB. Fixed μ=3 restricted to [50, 100] MHz; max sample rate capped at 122.88 MHz

3. Environment and Tooling

glm-ocr PDF rule in ~/.claude/CLAUDE.md is inherited by agents but not explicit in agent definitions — risk of built-in reader being used if task involves a PDF.
Pain Severity Detail Status Target fix
PyTorch version lag Low CC1 updated to 2.9.0 without verifying 2.10.0 was available. User had to point it out. Proactive version checking not done. Fixed Now on 2.10.0. Future: check latest before updating.
Ollama model cold-start overhead Med Ollama unloads models after 5 min of inactivity. In the review loop, each Claude call takes 2-4 min — model would be evicted between calls, causing cold-start delay every iteration. Fixed keep_alive: -1 added to Ollama API requests in orchestrate.py
PDF rule not propagated to agents Med Fixed PDF rule added explicitly to writer.md and reviewer.md
